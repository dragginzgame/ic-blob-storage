# Shared Tooling 0.9.0 adoption

Date: 2026-10-12. Blob remains released 0.22.11 at
`ebb560f492b6b53925faae8890316fc66bfd6def`; compatible pending notes remain
0.22.12. This contributor-tooling adoption changes no public library contract,
runtime behavior, stored schema, dependency requirement or MSRV.

## Source and selection

Canonical preview and refresh use committed Shared 0.9.0
`aec7a149f581a42b9531fc747b46024fc0314fcf` in a clean isolated checkout.
All 108 selected payloads and entrypoint roots remain. Only the verifier,
refresh helper and snapshot guide change payload bytes from the
[preceding 0.8.4 adoption](shared08402212.md). No file is added or retired;
central fleet reporting remains at its existing Shared owner.

The initial observed commit named 0.9.0,
`019ce8236cc7cee14ea5540d468b939a2053ef30`, still contained VERSION 0.8.4.
An initial refresh correctly retained that source annotation. Remote readback
then found the corrected commit; the final refresh records VERSION 0.9.0.
Both attempts remain retained. The sole difference between those commits is
VERSION; the exact executable and fixture inputs tested are unchanged.

Refresh now consumes the verifier's admitted manifest records instead of
independently parsing syntax. The reader captures one stream and rejects NUL
before splitting records. `--read-manifest FILE` emits ordered, byte-preserving
records only after complete syntax/duplicate/entrypoint-membership admission.
It does not check payload integrity, ownership or source trust. Ordinary
verification still checks hashes, modes and containment with an independent
checksum bootstrap; refresh still proves prior ownership against committed
source. Existing v1 manifests and consumer commands need no conversion.

## Focused verification and limits

The changed producer distribution fixture passes on Bash 5.2 and genuine Bash
3.2.57 on Linux. It exercises syntax-only reads without payloads or a checksum
backend, malformed/duplicate/unowned/NUL refusal with empty output, mixed-mode
refusal, payload corruption, companion closure, ownership and interrupted
atomic-copy retry. The consumer Make routing fixture also passes with substitute
release/format commands. Actual adopted-reader output agrees with the manifest's
ordered records on both shells; an appended NUL is refused with empty stdout.

Final snapshot integrity, dependency declarations, shell syntax/lint,
documentation references and diff checks pass. Root Cargo files, compiler/tool
pins and finalized receipt retain their pre-refresh hashes; the index remains
unchanged. Executable tool selections and build policy are unchanged, so prior
tool admission is not relabelled as new installation or product qualification.

Raw inputs, previews, both refreshes, logs and source-correction comparison remain
outside Cargo's build tree at `.tmp/review-validation/shared09002212/`.
[The earlier review](shared083-canic02212.md) retains its own installer and Canic
evidence. No full CI/release gate, fresh product/Canic build, native macOS, sibling
edit, staging, commit, version mutation, publication or paid effect is performed.
[Blob #59](https://github.com/dragginzgame/ic-blob-storage/issues/59) retains native
tooling/archive/transport acceptance; [Shared #133](https://github.com/dragginzgame/shared-tooling/issues/133)
owns shared manifest-reader admission.
