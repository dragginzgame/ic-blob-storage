# Shared Tooling adoption boundary

The superseded per-run adoption diary was compacted on 2026-11-05. The
[reviewed snapshot](../../.shared-tooling.snapshot) is the current file/hash/mode
inventory; [AGENTS.md](../../AGENTS.md) selects policy and local exceptions.
[Dependency setup](../dependencies.md) and the [handoff](../status/current.md)
record the current selection and focused consumer qualification.

Shared owns common formatting, release, setup, source classification and
validation mechanics. Blob owns package groups, product contracts, tool selection,
actual callers and their acceptance. Matching exported files do not prove that a
consumer workflow invokes them or that a release reused valid evidence.

Refresh only committed source through the canonical exporter, including companion
closure and reviewed additions/retirements. Check integrity and affected actual
callers. Ordinary adoption does not authorize release, broad qualification,
provider effects, a sibling edit or deleting active recovery records.

Routine test/adoption output is no longer a tracked evidence archive. Keep useful
conclusions in the current handoff/changelog or owning issue, and raw experimental
output under `target/evidence`. Apply the [retention rule](../../rules/engineering-details.md#changelogs-and-artifact-preservation)
without discarding protected provider/recovery or release records.

The historical diary and its failures remain in Git. References to removed run
reports point to exact pre-cleanup Git objects; local scratch paths and hashes
are not claims that raw artifacts remain available or independently verifiable.
